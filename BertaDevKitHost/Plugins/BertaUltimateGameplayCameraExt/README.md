# BertaUltimateGameplayCameraExt

Optional UE 5.8 Runtime/Editor integration for projects with a licensed local Ultimate Gameplay Camera installation. This plugin is disabled by default and contains no UGC source, content, or assets.

**Recommended UE 5.8 Sandbox setup:** Create a project-owned **Blueprint child of the vendor `BP_UGCCameraManager`**, for example `BP_SandboxUGCCameraManager`. In its **Class Defaults**, set **`Default Camera Data = DA_Camera_Medium`** (or the initial project-owned UGC Camera Data Asset). Assign this child as **`Player Camera Manager Class`** on the **existing** PlayerController; do not replace a GAS Companion / interaction Controller with the vendor demo Controller. Add `UBertaUGCCameraCycleComponent` to the same PlayerController. Set its ordered `CameraPresets` array to distinct, valid UGC data assets **including the exact asset selected as `Default Camera Data`**, e.g. `[DA_Camera_Medium, DA_Camera_Near, DA_Camera_Far]`. Use `Berta.UGC.Dump` in PIE to check Manager, ActivePreset, and CycleActiveIndex before `Berta.UGC.Next`. Optionally bind the project's own input actions to `SelectNextCamera()` / `SelectPreviousCamera()` or `SelectCamera(Index)` after verifying the console commands.

The C++ extension accepts any active `AUGC_PlayerCameraManager` or its derived class; **the child Blueprint is a recommended configuration pattern, not a specific hard-coded class requirement**. The important precondition is that a *non-null active* Camera Data Asset matches an asset **by object identity** in the component's `CameraPresets`. Adding the component or editing a Data Asset alone does not activate that preset.

Each operation reads UGC's current data asset. A known current preset determines the starting index; an unrelated active asset (such as a temporary aim camera) blocks selection without changing the stack or index. With no active asset, Next selects the first preset and Previous the last. Re-selecting the active preset succeeds without Pop/Push. A real change pops the current head, then pushes the requested asset so UGC remains responsible for its transition. Null or duplicate presets make the array invalid.

**Documented Sandbox failure and recovery (2026-10-20):** `Berta.UGC.Next` initially returned `success=false, storedCycleIndex=-1` while a vendor preset was active. Adding that vendor asset to the cycle alone **did not fix** the issue. After recommending the project-owned manager child with a project-owned `Default Camera Data`, the user confirmed **two visible Next changes** in PIE. The exact original early-return branch was not captured; `-1` is not diagnostic by itself. For any recurrence, check manager, ActivePreset, and CycleActiveIndex with Dump; validate non-empty/unique/valid `CameraPresets`, ensure the active preset belongs to the cycle, and inspect early returns from `SelectAdjacentCamera` / `SelectCamera` if needed. **Update (2026-10-20):** the Sandbox user has since confirmed successful packaging and that the resulting application works. Backup `07_UGC_CameraPresets_Validated` is recommended next but is **not yet confirmed as created**. Per-modifier packaged-build tests have not been separately reported.

Complete procedure, experimental preset values and root-cause caveats are in the [MkDocs UGC extension guide](https://nbertoa.github.io/ue5-bertadevkit/bertaultimategameplaycameraext/) and [R&D Engineer integration report](https://github.com/nbertoa/rnd-prototyping-engineer/blob/main/research/plugins/ultimate-gameplay-camera-sandbox-integration.md).

**UGC Dynamic Spring Arm — tested configuration (UE 5.8 Sandbox, PIE):** In the existing Third Person Character, introduce the vendor's `BP_UGCSpringArmComponent` (with `Do Collision Test` enabled) to replace the native `CameraBoom`. Reparent the existing `FollowCamera` to that UGC arm and **explicitly select `Parent Socket = SpringEndpoint`** (the same socket as on the original arm), with relative Location/Rotation `(0,0,0)`. Transfer baseline Spring Arm values and keep the UGC-specific collision defaults initially. **Remove the original `CameraBoom` after migration**, leaving only the UGC Spring Arm under the Character's `CapsuleComponent`. In the recorded Sandbox, leaving *both* arms caused centered framing and almost no distance differences between Near/Medium/Far; deleting the native arm fixed the visible issue. The exact component-selection mechanism was **not** proven with a before/after runtime Dump. The user then saw smooth wall-collision interpolation and predictive corner avoidance in PIE. **Important:** the earlier Windows package / backup 07 **predate** this Spring Arm migration; a new post-change package has not yet been confirmed. See the [MkDocs Dynamic Spring Arm procedure](https://nbertoa.github.io/ue5-bertadevkit/bertaultimategameplaycameraext/#dynamic-spring-arm-and-predictive-collision-tested-ue-58-migration) and the [Sandbox integration report](https://github.com/nbertoa/rnd-prototyping-engineer/blob/main/research/plugins/ultimate-gameplay-camera-sandbox-integration.md) for settings, final component hierarchy and test steps. The Spring Arm is **UGC's** feature; BertaDevKit does not reimplement collision.

The component maintains local, non-replicated selection state on the controller. It does not bind input, tick, manage possession, or write camera properties. Install Ultimate Gameplay Camera alongside this plugin and enable both only in the consuming project.

With the plugin enabled in the Editor, **Tools → Audit Ultimate Gameplay Camera** writes a read-only report to Output Log (`LogBertaUGCAudit`). It checks the global GameMode's PlayerController/camera-manager class, camera-cycle presets on that controller, and source-backed range/blend-duration rules in `/Game` UGC presets. Pawn-specific UGC setup checks apply only when the Global Default GameMode uses a UGC manager. A non-UGC manager is a **Warning** because map-specific GameMode overrides are outside this pass. It also identifies explicit Blueprint variable-set nodes for SpringArm arm length/offset and CameraComponent FOV, plus calls to `SetFieldOfView` and `SetControlRotation`. These graph findings are **Info**: a static write is only a possible conflict until its runtime target and execution are verified. The pass does not inspect C++ writes, map level scripts or map-specific GameMode overrides; Blueprint-inherited component overrides may need manual inspection. Unloadable assets and an incomplete Asset Registry are reported instead of being counted as clean.

Non-finite ranges and negative/non-finite blend times are reported as errors. Inverted Min/Max ranges are warnings because the UGC source shows mapped values but does not prove every reversal is invalid.

Select exactly two UGC camera data assets in Content Browser and choose **Compare UGC Camera Presets**. The read-only diff writes changed UGC base-property paths to Output Log (`LogBertaUGCPresetDiff`) with both values. Different concrete classes are reported as a `Class` difference, while common UGC base settings are still compared. It descends into reflected structs and instanced settings, lists array element/count changes, and compares curve and object references by asset path. Instanced settings that reach the recursion limit are reported as truncated/inconclusive separately from confirmed differences. It does not compare curve contents or custom fields defined only by a data-asset subclass.

For a locally controlled player in non-Shipping builds, `UBertaUGCCameraDebugLibrary::GetUGCCameraDebugSummary(PlayerController, OutSummary)` returns one text snapshot of the manager, Pawn, active UGC preset, active cycle index, final cached POV, SpringArm properties and UGC/external modifier counts. It returns `false` with an empty string for a non-local controller, a non-UGC manager, or Shipping. The UGC stack below its head and modifier priorities are intentionally outside this summary; UGC already provides `ShowCameraModifiersDebug` for detailed modifier inspection.

Non-Shipping builds register `Berta.UGC.Next [LocalPlayerIndex]`, `Berta.UGC.Previous [LocalPlayerIndex]`, `Berta.UGC.Select <CameraIndex> [LocalPlayerIndex]`, and `Berta.UGC.Dump [LocalPlayerIndex]`. The commands act only in the console's game world. With one local player the player index is optional; with split screen it is required. Selection commands use the controller's `UBertaUGCCameraCycleComponent` and preserve its rejection of an unrelated active UGC preset. `Dump` prints the read-only summary. Commands report invalid arguments, unavailable controllers/components, and selection failure in Output Log.
